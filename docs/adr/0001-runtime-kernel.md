# ADR-0001：Runtime Kernel 采用持久化状态机驱动模型

- **状态**：Accepted
- **日期**：2026-08-11
- **决策人**：Agent Runtime Maintainers
- **关联变更**：[E2026-08-11-001](../CHANGELOG.md#e2026-08-11-001)

## 背景

Agent 执行需要支持有界循环、失败收敛、事件审计、人工审批、暂停和恢复。若只把执行过程放在一次函数调用或内存对象中，进程退出后无法解释或恢复运行状态。

## 决策

使用 `AgentRun` 和显式 `RunStatus` 作为生命周期事实，由 `Runtime` 统一驱动模型调用、工具调用、审批、Checkpoint 和终态收敛。所有关键动作同时写入持久化 Event Log。

Run 只允许领域模型中声明的状态迁移；`completed`、`failed` 和 `cancelled` 为终态。

## 影响

### 优点

- 可以明确判断任务当前所处阶段。
- 可以审计模型、工具、审批和恢复过程。
- 可以在暂停或进程恢复时继续执行。
- 可以为未来 HTTP、SSE 和分布式 Worker 提供稳定生命周期语义。

### 代价

- Runtime 需要维护状态、事件和 Checkpoint 的一致性。
- 工具副作用需要进一步引入幂等协议才能保证分布式恢复安全。
- 状态机变化需要兼容旧数据并更新 ADR。

## 被放弃的方案

- 纯内存 Agent 循环：实现简单，但无法持久化、恢复和审计。
- 将生命周期交给模型自由输出：缺少确定状态和系统级安全边界。

## 后续约束

任何 Run 状态、终态语义、暂停/恢复行为或执行循环边界变化，都必须更新架构文档并新增或修订 ADR。
