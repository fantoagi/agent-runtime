# ADR-0030：有界文件读取与批量精确 Patch

- **状态**：Accepted
- **日期**：2026-08-17
- **决策人**：Agent Runtime Maintainers
- **关联变更**：[E2026-08-17-003](../CHANGELOG.md#e2026-08-17-003)

## 背景

完整读取大型文件会浪费模型上下文，单次 `replace_text` 也会让多文件修改产生大量 Tool 往返。Runtime 需要更适合真实编码任务的读取和修改协议，同时保持可验证和可审批。

## 决策

新增 `read_file_lines`，按起始行、最大行数和最大字符数读取 UTF-8 文件，并返回稳定行号、总行数、截断状态和 SHA-256。

新增 `apply_patch`，接受最多 20 条结构化精确替换。所有目标、字段、匹配数量和输入大小必须在任何写入前验证；写入使用既有原子文件替换。多文件执行失败时执行尽力回滚，回滚不完整则进入 `UNKNOWN`。该 Tool 声明 `file.write`、`requires_approval` 和 `side_effecting`。

## 影响

### 优点

- 大文件可以按范围读取，控制上下文消耗。
- 多个精确修改可以一次批准和执行。
- 匹配冲突会在写入前失败，避免部分业务修改。
- 每个修改文件返回前后 SHA-256，支持审计和 `/diff`。

### 代价

- `apply_patch` 不是 unified diff parser。
- 进程崩溃发生在多文件 replace 中间时仍可能留下部分修改。
- 不支持文件创建、删除、移动和二进制 Patch。

## 被放弃的方案

- 让模型每次读取完整文件。
- 直接执行模型生成的任意 unified diff。
- 在没有人工批准的情况下自动批量写文件。

## 后续约束

未来若引入完整 Patch 引擎，必须保持 Workspace confinement、预写入验证、可审计结果和 UNKNOWN 语义，不能把多文件操作描述为跨崩溃原子事务。
