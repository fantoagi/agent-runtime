# ADR-0004：工具必须注册、校验并限制在 workspace 安全边界内

- **状态**：Accepted
- **日期**：2026-08-11
- **决策人**：Agent Runtime Maintainers
- **关联变更**：[E2026-08-11-001](../CHANGELOG.md#e2026-08-11-001)

## 背景

模型输出属于不可信输入。允许模型直接执行任意 Python、Shell、文件路径或网络请求，会让 prompt injection 和参数构造转化为宿主机副作用。

## 决策

所有工具必须通过 `ToolRegistry` 显式注册，并包含名称、描述、输入 schema、handler、超时和审批要求。执行前校验参数；文件路径必须解析后确认仍位于配置 workspace 中；写文件等高风险工具可以要求人工审批。

首版不提供任意 Shell、自动依赖安装或宿主机进程管理。未来代码执行必须通过独立 `SandboxExecutor`，不能直接扩展当前受控工具为无限制执行器。

## 影响

### 优点

- 模型只能访问显式授权能力。
- 参数错误和工具异常可以被标准化处理。
- workspace 越界和高风险副作用有明确防线。

### 代价

- 每个工具都需要 schema 和安全审查。
- 当前基础校验器不是完整 JSON Schema 实现。
- 进程级限制不能替代容器或虚拟机级强隔离。

## 被放弃的方案

- 将模型生成内容直接交给 Shell。
- 允许文件工具访问任意绝对路径。
- 默认允许所有工具副作用且不保留审批记录。

## 后续约束

新增网络、Shell、代码执行、凭据或系统资源工具时必须进行安全评审并新增 ADR。任何路径边界放宽都视为 breaking security change。
